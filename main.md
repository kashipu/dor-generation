# Master de Gobernanza: Framework de Investigación UX (V. 2025)

## 1. Contexto Global y Propósito
Este ecosistema documental es el **sistema operativo de investigación** del equipo de diseño. Su propósito es centralizar el ciclo de vida de la investigación, eliminando la subjetividad y asegurando que cada iniciativa responda a los **OKRs (Objetivos Clave)** de negocio.

Mediante la validación temprana con usuarios, buscamos mitigar tres riesgos críticos:
*   **Riesgo de Valor:** ¿Estamos construyendo algo que la gente realmente quiere?
*   **Riesgo de Usabilidad:** ¿Pueden los usuarios entender cómo usarlo?
*   **Riesgo de Negocio:** ¿Esta solución apoya los objetivos estratégicos de la organización?

## 3. Relación Lógica del Proceso (Workflows)

Para que el framework sea efectivo, siga este flujo de trabajo:

1.  **Priorizar:** Evaluar la idea en [ICE-R](file:///c:/Users/williamm/Desktop/research/ice-r.md). Si el riesgo es alto, se justifica una investigación profunda.
2.  **Planear:** Formalizar el compromiso en el [DoR](file:///c:/Users/williamm/Desktop/research/dor.md) declarando objetivos e hipótesis.
3.  **Ejecutar:** Seleccionar el método en [Protocolos](file:///c:/Users/williamm/Desktop/research/protocolos.md). Si es un test de usabilidad, seguir el [Protocolo de Testeo](file:///c:/Users/williamm/Desktop/research/protocolo-testeo.md).
4.  **Analizar:** Procesar los hallazgos en la hoja de [Análisis](file:///c:/Users/williamm/Desktop/research/analisis.md).
5.  **Cerrar:** Documentar Insights y Accionables en el [DoD](file:///c:/Users/williamm/Desktop/research/dod.md) y archivar según la [Intro](file:///c:/Users/williamm/Desktop/research/intro.md).

## 4. Glosario de Términos Clave
*   **SUS (System Usability Scale):** Métrica obligatoria de usabilidad percibida para flujos críticos.
*   **Insights:** Hallazgos que combinan observación, evidencia (Verbatim) y oportunidad de mejora.
*   **Tribu:** Célula de trabajo orientada a un producto específico (ej. Vivienda, Crédito, Canales).
*   **JTBD (Jobs to be Done):** Misiones específicas que el usuario debe completar para validar el flujo.
*   **Verbatim:** Cita textual del usuario que sirve como prueba irrefutable de un hallazgo.
